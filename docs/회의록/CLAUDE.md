# 회의록/ — 7장 정본 · 회의 기록이 들어오면

> 처리 시점은 회의가 들어온 ★즉시★다 (17장).
> ★이 파일은 회의 기록을 받은 순간 먼저 읽는다★ — 회의록/ 파일을 만들기 시작하면 이미 늦다 (0장).
> 계기와 장 지도는 루트 CLAUDE.md 에 있다. 최종 확인: 2026-08-18
> 반증 조건: 없음 — 규칙은 합의다 (13장)
> 재론 조건: ★네 절 중 어디로 보낼지 모르는 항목이 나왔을 때★ · 본문이 원문보다 짧아졌을 때 ·
>            발언과 붙어 온 것을 가르기 애매한 기록이 들어왔을 때

## 7. 회의 기록이 들어오면

3장이 "대화 로그를 손으로 다시 쓰지 말라"고 한 건 `*.jsonl` 로 **이미 남는 경우**다.
사람끼리의 회의는 아무 데도 안 남는다 — 원문을 받아 보관하고, 읽을 수 있게 정리한다.

```
원본/회의/YYYY-MM/YYYY-MM-DD_회의명.md   ★원본★ · 받은 그대로 · 한 글자도 안 고친다
회의록/YYYY-MM/YYYY-MM-DD_회의명.md      읽는 곳 · 정리본 + 머리말
```

★월 폴더와 파일명을 원본과 똑같이 맞춘다★ — 짝이 맞는지 눈으로 바로 보이게 (16장과 같은 규칙).

### 8장에서 ★일부만★ 상속한다 — 그래서 이름도 다르다

```
상속한다     진위 우선순위 — "갈라지면 ★원본★이 이긴다"
상속 안 한다 수정 위치 — 8장은 "수정은 정본에만"인데, 여기 원본은 못 고친다
             그래서 ★수정은 사본(회의록)에서 한다★
```

**왜 `정본` 이라 안 부르나**: 8장의 정본은 **수정을 모으는 편집 가능한 원본**이고,
여기 원본은 **한 글자도 못 고치는 원자료**다. 같은 말로 부르면 "수정은 정본에만"이
여기서는 수정을 불가능하게 만든다. 10장대로 **나중에 만든 쪽(7장)이 이름을 바꾼다.**

★16장의 스냅샷도 같은 뜻의 `원본` 이다★ — 못 고치는 원자료. 다만 스냅샷에는
사본이 따로 없다 (사본에 해당하는 것이 사건 문서 자신이고, 그건 계속 옮겨 다닌다).

### 정리는 하되 ★요약하지 않는다★

```
해도 되는 것   안건별로 묶기 · 제목 달기 · 순서 정리 · 화자 표기 정돈
안 되는 것     ★발언을 지우는 것★ — 그건 요약이고, 요약은 원본에 진다
```

- 안건 제목은 **회의에서 실제로 쓴 말**로 단다. 새 용어를 만들지 않는다.
- 사소해 보여도 지우지 않는다 — **한 문장이 결론 전체를 지탱하는 경우가 흔하다** (3장).
- 머리말에 **"원본은 원본/회의/… 다. 갈라지면 원본이 이긴다"**
- ★오타로 보여도 본문에서 고치지 않는다★ — `회갑` 을 `회갑(회원가입)` 으로 만드는 순간
  **추측이 발언인 척한다.** 고칠 거리는 인용 밖에 단다 (3장과 같은 규칙).

### ★발언과 ‘붙여 온 것’ 을 절로 가른다★ — 계기는 발언 쪽에서만 나온다

회의 기록에는 사람이 한 말만 들어오지 않는다. 남이 써준 기획안·모델이 뽑아준 권고문·
전에 만든 문서가 **통째로 붙어서** 같이 온다. 둘을 안 가르면 **7장이 3장에 잘못된 원료를 넘긴다.**

```
## 본문        ★그날 사람이 한 말★ — 여기서만 계기를 뽑는다
## 붙어 온 것  회의 자리에 올라온 남의 문서 · 권고문 — ★출처와 함께★ 그대로 둔다
```

**둘 다 지우지 않는다** — 가르기만 한다. 붙어 온 문서도 그날의 자료라 원자료다.
다만 그건 *"왜 하기로 했나"* 의 답이 아니라 **참고한 것**이고, 사건 문서에서는
`계기` 가 아니라 `하기로 한 것` 의 근거로 내려간다 (3장).

★가르는 표시는 원문에 없다★ — 그래서 이건 사본에서만 하는 일이고, 판단이 들어간다.
애매하면 `## 붙어 온 것` 으로 보낸다. **발언이 아닌 것을 발언으로 보는 쪽이 더 비싸다** —
계기가 오염되면 그 사건 문서 전체가 잘못된 이유 위에 선다.

### 사본을 고칠 때 — ★매번 분량을 잰다★

원본을 못 고치므로 사본이 유일한 수정 지점이다. 그래서 검사를 수정 쪽에 붙인다.

```
수정 후 짧아졌다  → 원본과 대조한다 — ★발언이 지워졌으면 되돌린다★
                   (중복 문단·오기 정리처럼 정당하게 줄어드는 경우만 통과)
길어지거나 같다   → 제목·오타·순서 교정. 통과
```

**왜 절대 길이가 아니라 수정 전후 비교인가**: "원문과 비슷한 길이"는 한 줄 삭제를
통과시킨다. 전후 비교는 제목 추가(늘어남)·오타 교정(그대로)·삭제(줄어듦)를
정확히 가른다. **7장이 무서워하는 건 추가가 아니라 삭제다.**

★검사가 둘인 것은 잴 수 있는 것이 순간마다 다르기 때문이다★ — 하나가 다른 하나를
폐기한 게 아니다:

```
만들 때  비교 대상이 원문뿐이다   → ★본문 대 원문★ (아래 '분량이 검사다')
                                    거친 검사다 — 한 줄 삭제는 못 잡는다
고칠 때  직전 사본이 있다         → ★수정 전후★ (이 절)
                                    촘촘한 검사다 — 한 줄 삭제를 잡는다
```

**만들 때의 검사가 거친 것은 어쩔 수 없다** — 그 순간에는 대조할 사본이 없다.
그래서 ★고칠 때마다 촘촘한 쪽이 돈다★. 회의록은 한 번 만들고 여러 번 고치므로,
삭제를 실제로 막는 것은 이 절이다.

**왜 매번 재나**: 전량 재정리는 비싼 대신 원본 대조가 강제됐다.
한 줄 수정은 싸고 아무것도 대조하지 않는다 — 그 싼 비용에 검사를 붙여야
"두 벌이 조용히 갈라지는" 게 막힌다.

### 머리말 네 절 — 이게 흘려보내는 표다

각 절이 곧 목적지다. 분류표를 따로 두지 않는다.
★분류는 즉시 하되, 실제 이관은 처리 범위 확인과 대조(아래) 뒤에 한다★ —
보관·정리만 또는 읽기 전용 요청이면 이관하지 않는다.

```
## 결정         → 상시 문서 / 백로그로 옮기고 여기엔 결과만 (4장)
## 일단 이렇게  → ★잠정/ 에 사건 문서★ (3장) · `가정` 칸에 `뒤집힘 비용` 까지
## 미결         → 결정대장 ①-N · `막히는 것` 같이 · ★주체가 사용자가 아니어도
                  답이 사용자를 거쳐 오면 ①절★ (4장)
## 액션         → ★아래 4분법으로 판정★ — 활성 합의만 잠정으로
```

**둘째 절이 회의의 주 수확이다.** *"그건 나중에 정하고 일단 가시죠"* —
사건이 태어나는 전형적인 자리이고, 이게 아무 데도 안 남는 게 기본값이다.

**액션은 4분법으로 판정한다 — 위에서부터 먼저 맞는 곳으로:**

```
1 합의했지만 명시적으로 유예됨      → 백로그 — 활성화 계기는 잠정 카드의 단건/다건
                                     분기 그대로 (5장): ★사건 하나만 여는 지시면 그
                                     지시 원문★ · ★여러 사건을 열면 각 항목의 최초 합의
                                     원문★ (공통 지시는 활성화 근거 — 3장 · 묶음은
                                     원인·종결 단위) · 새 잠정이 ★이어받은 것을 확인한
                                     뒤★ 항목 삭제 (9장)
2 지금 할 다음 행동이 있는 합의     → ★잠정/ 에 사건 문서★ (3장)
3 결정이 필요한 제안               → ## 미결 (①-N · 4장)
4 수용되지 않은 단순 제안          → 파생 문서 없음 — 회의록 본문에는 그대로 남는다
```

★잠정 = 합의됨 + 지금 활성★이다. 담당이 미정이어도 합의됐으면 잠정에 간다 —
배정이 착수의 전제인 항목만 그 결정을 확정 조건으로 올린다 (3·5장).

**★회의 정리는 착수가 아니다★** — 정리 · 파생 사건 생성 · 담당 기록 · 확정 판정 ·
링크 작성 전부. 정리하는 모델은 실행자가 아니라 ★기록자★다. 사건은 잠정에 태어나
★착수 근거★가 생길 때만 움직인다 (5장). 항목의 담당·완료 신호는 회의록 머리말이
아니라 ★파생 사건 문서의 칸★에 적는다 — 머리말 분량 규칙은 그대로다 (아래).

### 여러 항목이 한 사건으로 묶일 때 — 계기는 하나다 (3·9장)

```
최초의 유효한 합의 발언          → `계기`
같은 범위의 후속 합의·인용       → 각 계획 항목의 근거로 내린다
합의된 목표의 필수 단계 분해      → 인용 없이 항목이 될 수 있다
합의 범위를 ★넓히는★ 항목       → 추가 지시 없이 넣지 않는다
나누는 기준                     → 원인·독립 종결 단위 (9장) — 인용 유무가 아니다
어느 합의에도 안 속하는 항목     → 나누는 게 아니라 재분류한다 (미결·백로그·무문서)
```

각 항목에 **본문 인용 한 줄**을 건다. 그 항목이 ★독립 사건으로★ 열리면 그 인용(최초
합의 발언)이 머리말 계기가 된다 (3장) — 같은 걸 두 번 쓰지 않는다. 여러 항목이 한
사건으로 묶이면 위 묶음 규칙대로 ★최초 합의만 계기★이고 나머지는 항목의 근거다.

**처리 시점은 회의가 들어온 즉시다.** 단락이 끝날 때까지 미루면 그때는 이미 흐려져 있다.

### 대조 — ★정리 다음 단계다★ (처리 범위가 허용할 때 · 아래)

후보는 머리말에서 찾고 ★판정은 원본 구절로 검증한다★ — 사본은 갈라질 수 있다 (8장).
★현재 상시 정본과 열린 사건을 먼저 대조한다.★ 그 둘로 판정이 안 될 때만 관련된
이전 회의 ★원본★을 연다 — 매번 전체 회의를 재생하지 않는다. 과거 회의를 한꺼번에
받았으면 회의 날짜순으로 본다.

```
권한 있는 명시적 합의·결정이 앞 상태를 바꾼다
    → 기존 네 절의 목적지로 반영 후보
★실제 시작·결과 보고★다
    → 네 절이 아니라 ★연결된 사건★을 찾아 착수·실행 상태를 갱신한다 (5·14장)
      연결된 사건이 없으면 → 5장 사후 복구 판정 · 어느 사건인지 불명이면 → 질문
앞 범위가 언급되지 않고 ★경쟁 범위가 같은 자리를 차지★했다
    → 전환 여부 질문
단순 미언급
    → ★아무 판정도 하지 않는다★ — 그날 안건이 아니었을 수 있다
같은 작업이 다시 등장했으나 기존 사건의 진행 기록과 연결되지 않는다
    → 진행 상태 질문 ("미착수"로 판정하지 않는다 — 진행 증거가 문서에 없을 뿐이다)
원본 내부가 서로 어긋난다 (날짜·요일 · 수치 · 구성 정의)
    → 사실 확인 질문
```

★추론·미언급·반복만으로 현재 상태를 바꾸지 않는다★ — 근거가 없으면 질문이 결과다.
일정표의 목표치("1주차: X 완료")는 결과 보고가 아니다 — 시제와 문맥을 원본에서 본다.

### 처리 범위 — 어디서 멈추나

```
보관·정리만 요청       → 원본과 회의록을 만든 뒤 종료
읽기 전용 검토 요청    → 대조·후보·질문까지 ★화면으로★ 보고하고, 파일 반영 전에 종료
반영 요청             → 권한·원본 근거가 확인된 후보만 반영한다 —
                        합의·결정은 네 절의 목적지로 · ★시작·결과 보고는 연결된 사건으로★
과거 회의 일괄 입력    → 어떤 모드든 지나간 사건 생애주기·스냅샷을 ★소급 생성하지
                        않는다★ (이유는 5장 사후 복구와 같다) — 현재 상태 후보만
                        보고하고, 복구 요청이 있을 때 앞으로 남은 일만 반영한다
```

라우팅을 생략한 사실은 ★회의록에 적지 않는다★ (네 절은 표다) — 화면 보고로만 남긴다.

### 분량이 검사다

```
본문   원문과 ★비슷한 길이가 정상★ — 절반으로 줄었으면 요약한 것이다
머리말 ★항목마다 한 줄 + 인용 한 줄까지★ — 설명을 달지 않는다
```

**★잴 때 머리말을 뺀다★** — 이게 이 검사의 급소다. 통째로 재면 머리말이 길어진 만큼
본문이 줄어도 총합은 늘어나고, **삭제가 통과한다.** 전체 줄 수가 늘었다는 것은
아무것도 증명하지 않는다. ★본문 대 원문으로 잰다.★

**머리말에 설명이 붙기 시작하면 그건 사건 문서의 계기다** — 네 절은 목적지로
흘려보내는 표이지 두 번째 본문이 아니다. 설명하고 싶어졌다는 것은 그 항목이
사건 문서를 열 만큼 크다는 뜻이고, **설명은 거기 가서 쓴다** (3장).

해당이 없는 절은 지우지 말고 ★`없음` 한 줄★을 남긴다 — 액션 없는 회의도 있고,
그건 그렇게 적는다. 빈칸(누락)과 `없음`(판단)이 다른 이유는 ★13장 정본★.

> 회의 원문에는 사람 이름과 그날의 발언이 그대로 들어간다.
> 원자료는 고치지 않는 게 원칙이므로, **나가면 안 되는 내용이면 애초에 넣지 않는다** —
> 들어온 뒤에 지우는 길은 이 규약에 없다.
