## 14. 실행 누적 — ★계획을 고치지 않고 그 아래에 쌓는다★

문서가 여기 오면 두 절이 붙는다: `## 실행`(계획 항목을 하나씩 처리하며 그 자리에서
결과를) · `## 계획 밖`(계획에 없던 것 — 계획 칸을 고치지 않고 여기에).

```
★안 고친다★  `계기` · `하기로 한 것` 의 ★항목 문장★   ← 이 둘이 대조의 기준선이다
고친다        체크박스 [ ] → [x]/[~]/[-]              항목 문장은 그대로 두고 표시만
              `상시로 갈 것`                          실행 중 한 줄씩 적립 (아래)
              `종결 조건`                             ★바꿨으면 `## 계획 밖` 에 왜인지★
              상태 표기 → [종결]/[폐기]                종결 때 한 번 (6장 ③)
```

★계획을 고치면 계획과 실제가 같아지고, 그 순간 이 문서는 아무것도 안 알려준다★ —
종결 때 남는 가장 큰 값은 "처음 생각과 어디가 달랐나"다 (04_규약근거.md 14장).
계획 스냅샷이 원본/잠정/ 에 있어도 여기서 안 고친다 — 한 문서 안에서 위아래로
보여야 대조가 실제로 일어난다.

```
항목대로 됐다          → [ ] 를 [x] 로 · ## 실행 에 결과 한 줄
항목이 틀렸다/불필요    → [ ] 를 [~] 로 · ★항목 문장은 그대로 두고★ ## 계획 밖 에 왜인지
안 하기로 했다          → [ ] 를 [-] 로 · ## 계획 밖 에 왜인지
계획에 없던 걸 했다     → ## 계획 밖 에 새 줄 · ★위에는 안 올린다★
★새 지시가 왔다★       → ## 계획 밖 에 ★사용자 말 원문 그대로★ + 그래서 뭘 더 하게 됐는지
                         ★`계기` 칸에 이어붙이지 않는다★ (3장 — 계기는 하나뿐이다)
```

`종결 조건` 은 고쳐도 된다 — 실행해 보면 잴 수 없는 조건이었음이 드러난다.
★고치되 흔적을 `## 계획 밖` 에 남긴다★ (04_규약근거.md 14장).

### `## 실행` — ★그 자리에서 적는다★

```
적는다        실측값 · 실패와 그 원인 · 판단이 갈린 지점과 고른 쪽
안 적는다     명령 로그 · 코드 diff — 그건 저장소와 대화 로그가 갖는다
```

나중에 몰아 쓰면 회고가 되고, 회고는 잘된 것만 적는다. ★실패를 지우지 않는다★ —
헛돈 시도가 다음 사람이 가장 아쉬워하는 기록이다 (04_규약근거.md 14장).

### `상시로 갈 것` — 실행 중에 적립한다

"끝나도 남는 지식"이 나온 ★그 순간★ 머리말 칸에 한 줄 — 어디로 옮길지까지 적으면
종결 때 판단이 필요 없다. 종결 순간까지 판별을 미루면 건너뛰게 된다 (04_규약근거.md 14장).

## 6. 종결 절차 — ★순서가 중요하다★

```
① 계획 항목이 전부 [x]/[~]/[-] 인가 · 종결 조건이 찼는가 확인
② ★원본/진행중/YYYY-MM/ 에 이 시점 그대로 복사★ (16장) — ★아무것도 고치기 전이다★
③ 머리말을 [종결]로 (종결일 · 결과 한 줄 · 후속 링크)
④ ★'상시로 갈 것' 적립분을 상시 문서로 이관★ — 옮긴 줄마다 출처 사건 파일명 (13장)
     옮길 것: 원칙 · 기제 · 재론 조건   /   남길 것: 그날의 실측 · 경과 · 계획과의 차이
⑤ 그다음 종결/YYYY-MM/ 으로 ★이동★ (이름 안 바꾼다)
⑥ ★경로가 박힌 링크만★ 고친다 (회의록 머리말 등)
     결정대장 ①절 `사건` 칸은 파일명뿐이라 고칠 게 없다 (4장)
     상시 문서가 새로 생겼으면 00_구조.md 의 트리와 `## 읽는 순서` 에 넣는다
```

★②가 급소다 — 정리(③④)한 뒤에 뜨면 정리하기 전을 담을 수 없다★ (04_규약근거.md 6장).
①은 확인이지 수정이 아니라서 ② 앞에 있어도 된다. ④를 건너뛰면 지식이 조용히
사라진다 — 적립이 비었으면 여기서 한 번 훑되, 매번 그러면 고칠 곳은 14장이다.

★단계 번호는 2026-08-12 에 한 번 옮겼고 다시는 옮기지 않는다★ — 그 이전의 단계 번호
인용은 옛 순서다 (대조표: 04_규약근거.md 6장).

### 실행 중에 접기로 하면 — ★같은 문으로 나간다★

```
① 남은 항목을 [-] 로 · `## 계획 밖` 에 왜 접는지   ← '확인'이 '표시'로 바뀌는 것만 다르다
② 스냅샷 — ★그대로★ (접는 것도 정리 전에 뜬다)
③ 머리말을 ★[폐기]★ 로 (폐기일 · 왜 죽었나 한 줄)   ← [종결] 대신 이것만 다르다
④⑤⑥ 그대로 밟는다 — ★④(이관)를 특히 건너뛰지 마라★: "이 방법은 안 된다"도
     성공한 결론만큼 값이 나간다 (04_규약근거.md 6장)
계획이 통째로 틀려서 접는 것이면 → 이어서 잠정/ 에 새 계획 (15장과 같은 모양)
```

★진행중 → 잠정 으로 되돌아가지 않는다★ — 스냅샷이 두 벌이 되어 어느 쪽이 그 사건의
계획인지 알 수 없게 된다 (04_규약근거.md 6장). 접는 것과 다시 세우는 것은 다른 문서다.
