## 최종 기술 스택

| 영역 | 선택 | 이유 | 출처 사건 |
|---|---|---|---|

**(아직 안 정함 — 첫 선택이 나면 여기에 한 행)**

★빈 표는 "스택이 없다"가 아니라 "아직 안 정했다"이다.★ 그래서 비워두고 그렇게 적는다 —
빈칸(빠뜨림)과 `아직 안 정함`(판단)은 다르다 (★13장 정본★).

### 네 열이 무엇인가 — ★`이유` 열이 이 문서의 심장이다★

```
영역      프론트 · 백엔드 · DB · 큐 · 검색 · 인프라 … ★한 영역에 한 행★
선택      골라진 것 하나 · ★버전 하한이 조건이면 같이★ (예: `Postgres 16+`)
이유      ★왜 그걸 골랐나★ — 이게 없으면 나중에 못 뒤집는다 (아래)
출처 사건 그 선택이 종결된 사건 파일명 (13장) · 회의에서 정해졌으면 회의록 파일명
```

**`이유` 가 3장의 `계기` 와 같은 역할이다.** 결론만 남으면 *"왜 그때 그걸 골랐나"* 가
날아가고, **나중에 그 선택을 뒤집어야 할 때 필요한 게 정확히 그것이다.**
"팀에 익숙해서" 와 "성능 때문에" 는 뒤집힐 조건이 완전히 다르다 —
전자는 팀이 바뀌면 죽고, 후자는 부하가 바뀌면 죽는다. **이유가 곧 유효 기간이다.**

★`확정` 처럼 이유가 아닌 말을 쓰지 않는다★ — 그건 "정해졌다"의 동어반복이고,
왜 정해졌는지를 감춘다. 근거가 없으면 ★`근거 없음 — 관행`★ 이라고 쓴다 (4장과 같은 규칙).

## ★바꿀 때 — 표를 고치지 않는다. 사건을 연다★

기술 스택은 바뀐다. 그런데 9장은 상시 문서에 대해 *"틀린 줄은 지우고 맞는 내용으로
다시 쓴다"* 고 한다. **그대로 하면 옛 선택의 `이유` 가 사라진다.**

```
잠정/ 에 새 계획          계기 = 왜 바꾸기로 했나 (원문) · 하기로 한 것 = 이관·검증 항목
   ▼
진행중/ 에서 실측          ★옛 선택이 실제로 왜 안 되는지가 여기 쌓인다★
   ▼
종결 때 이 표의 행을 교체  선택·이유·출처 사건을 새것으로 · ★옛 행은 지운다★
```

**옛 이유는 지워도 안 사라진다** — 종결 문서에 그대로 있고, 표의 `출처 사건` 열이
거기로 가는 유일한 통로다. ★그래서 `출처 사건` 열이 비면 이 절 전체가 무너진다.★

**표에 옛 선택을 남기지 않는다** — `~~Flask~~ → FastAPI` 같은 취소선은 개정 이력이고,
9장이 금지한 *"예전엔 X였다"* 다. **지금 유효한 것만 여기 있다** (13장).

## 여기 안 적는 것

```
검토했지만 안 고른 것    → 그 선택을 낳은 사건 문서에 (거기가 계획과 실제의 차이를 담는다)
아직 안 정한 것          → 03_결정대장 ①절 또는 ②절 (4장) · ★이 표에 빈 행을 만들지 않는다★
"고쳐야 하는데 지금은 아니다" → NN_백로그.md (생기면 그때)
설정값 · 명령어 · 버전 픽스 → pyproject.toml · package.json · Dockerfile 이 정본이다
```

**마지막 줄이 중요하다.** 실제 설정을 여기 옮겨 적으면 두 벌이 되고,
**두 벌은 조용히 갈라진다** (8장). 여기는 ★무엇을 골랐나★ 까지다.

## 반증 조건을 바꿀 때 — ★코드가 생기면★

지금은 대조할 대상이 없어 `없음 — 합의` 다. **코드가 생기는 순간 이 문서는
13장이 말한 "명령으로 쓸 수 있는" 종류가 된다** — 그때 머리말을 바꾼다:

```
반증 조건: 아래 출력의 주요 의존성이 이 표와 다르면 이 문서가 낡은 것이다
           Get-Content pyproject.toml     ← 백엔드·품질·ORM·큐
           Get-Content package.json       ← 프론트·UI
           docker compose config          ← DB·인프라
```

★그때 `재론 조건` 은 지운다★ — 13장이 "재론 조건은 반증 조건이 `없음` 일 때만 쓴다"고
했고, 둘 다 있으면 어느 쪽이 트리거인지 모른다.

## 재론

**반증 조건이 `없음` 인 동안 이 문서를 다시 여는 조건이다** (13장).

```
· 새 영역이 생겼다 — 표에 없는 층을 쓰기 시작했다 (예: 캐시 · 인증 · 모니터링)
· 어떤 행의 `이유` 가 더는 사실이 아니다 — ★그 이유가 지목한 조건이 바뀌었을 때★
· 첫 코드가 올라왔다 → 반증 조건을 명령으로 전환 (위)
```

**둘째 줄이 이 문서가 사는 방식이다.** `이유` 를 적어두면 무엇이 바뀌었을 때
다시 열어야 하는지가 행마다 자동으로 정해진다 — **재론 조건을 따로 관리하지 않아도 된다.**
