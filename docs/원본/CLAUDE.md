## 16. 여기 들어오는 것 — 두 갈래다

```
스냅샷    사건 문서가 폴더를 넘어갈 때 그 시점 그대로 복사한 것   ★이 장★
회의 원본 사람에게서 받은 그대로의 회의 기록                     7장
```

```
원본/잠정/YYYY-MM/YYYY-MM-DD_제목.md     ★확정 시점★ — 진행중/ 으로 옮기기 직전 (5장 ②)
원본/진행중/YYYY-MM/YYYY-MM-DD_제목.md   ★종결 시점★ — 종결 정리를 ★시작하기 직전★ (6장 ②)
원본/회의/YYYY-MM/YYYY-MM-DD_회의명.md   받은 그대로 (7장)
```

**★파일명과 월 폴더를 사본과 똑같이 맞춘다★** — 짝이 맞는지 눈으로 바로 보이게.
한 사건이 끝나면 같은 이름이 ★세 곳★에 있게 된다 (옮겨 다니는 파일이 곧 종결본이다):

```
원본/잠정/2026-08/2026-08-12_ASOS수집.md     계획이 확정됐을 때 이랬다
원본/진행중/2026-08/2026-08-12_ASOS수집.md   실행이 끝났을 때 이랬다
종결/2026-08/2026-08-12_ASOS수집.md          최종본 (= 위와 같다)
```

**★폐기된 사건은 벌 수가 다르다★** — 뜬 시점까지만 있는 게 정상이다:

```
잠정에서 폐기    스냅샷 ★0 벌★ · 종결본만  ★뒤에 다시 쓰는 단계가 없다★ (5장)
진행중에서 폐기  스냅샷 2 벌 · 종결본       6장 절차를 밟으므로 완주와 같다 (6장)
```

**★확정을 거치지 않은 문서가 `원본/잠정/` 에 있으면 안 된다★** — 스냅샷을 뜨는 시점은
확정 하나뿐이다 (5장 ②). 여기 있는데 아직 `잠정/` 에 원본이 있으면 이동이 끊긴 것이다 (11장).

## 왜 두 번 뜨나 — ★잃는 것이 서로 다르다★

```
잠정 스냅샷    실행이 계획을 덮는 것을 막는다
               항목이 바뀌고 늘면서 "처음에 뭘 하려 했나"가 조용히 사라진다
진행중 스냅샷  종결 정리가 실행 기록을 덮는 것을 막는다
               6장 ③·④(머리말 [종결] · 지식 이관)이 문서를 다시 쓰는 단계다
```

**진행중 스냅샷은 종결본과 대개 같다.** 그래도 뜬다 — 다른 날이 문제이기 때문이다.
종결 정리에서 무엇을 지웠는지는 지운 뒤에는 알 수 없고, 지우는 손은 자기가
지운 걸 기억하지 않는다.

★그래서 뜨는 시점은 ★손대기 직전★이다.★ — 이동 직전이 아니다.

```
잠정 스냅샷    5장 ② — ①(확정 조건 갱신) 뒤. ①은 덮는 행위가 아니라 앞에 둬도 된다
진행중 스냅샷  6장 ② — ★③④(머리말 · 이관) 앞★. 그 둘이 문서를 다시 쓴다
```

**둘의 공통 규칙은 "이동 직전"이 아니라 ★"다시 쓰기 직전"★ 이다.** 잠정 쪽은 그 둘이
우연히 같은 자리라 오래 "이동 직전"으로 불렸지만, 종결 쪽은 다시 쓰는 단계가
이동보다 앞에 있어 갈린다. **정리한 뒤에 뜨면 이 장 전체가 형식만 남는다.**

## git 이 있는데 왜 또 뜨나

이 저장소는 버전 관리 아래 있고, 지운 기록·개정 이력은 git 담당이다 (9장).
그래도 스냅샷은 뜬다 — ★겹치는 건 보관이지 역할이 아니다★:

```
시점이 다르다      git 은 커밋의 순간을 남기고, 스냅샷은 ★확정·종결이라는 사건의 순간★을
                   남긴다 — 둘이 일치한다는 보장이 어디에도 없다
보이는 곳이 다르다  스냅샷은 폴더를 열면 있고 2장의 grep 한 줄에 걸린다 —
                   히스토리는 찾으러 가는 사람에게만 보인다
```

git 으로 스냅샷을 대신하려면 "확정마다 반드시 커밋한다"는 규율이 추가로 필요한데,
그게 지켜졌는지 나중에 확인할 길이 없다. 파일 복사는 5장 ②·6장 ② 절차에 이미 박혀 있다 —
★절차가 담보하는 쪽을 정본으로 삼는다.★ 커밋을 언제 하나는 이 규약이 정하지 않는다.

## 규칙

- **받은/있던 그대로 보관한다.** 여기 들어온 파일은 어떤 이유로도 안 고친다.
- 안의 옛 표기는 당시 사실이다 — 고치면 안 된다 (11장).
- **여기서 링크가 깨져도 안 고친다.** 스냅샷은 그날의 문서이지 지금의 문서가 아니다 —
  깨진 링크 자체가 "그때는 저기 있었다"는 정보다. (종결/ 은 반대다 — 15장의 예외 하나.)
- 회의 원본의 정리·수정은 사본(`회의록/`)에서만 한다 → 회의록/CLAUDE.md 의 7장.
- **나가면 안 되는 내용이면 애초에 넣지 않는다** — 들어온 뒤에 지우는 길은 이 규약에 없다 (7장).
  ★스냅샷도 마찬가지다★: 잠정·진행중 문서에 키·비밀번호를 적으면 그게 그대로 여기 박힌다.
