# 00_구조 — docs/ 가 어떻게 생겼나 · ★구조의 정본★

최종 확인: 2026-08-12
반증 조건: 아래 두 명령의 출력에 ★이 문서에 없는 것★이 있으면 이 문서가 낡은 것이다

```
Get-ChildItem docs -Recurse -Directory -Name     ← 폴더
Get-ChildItem docs -Filter *.md -Name            ← docs 루트의 파일 (CLAUDE.md 도 나온다 — 트리에 있다)
```

★자리표시자는 패턴으로 대조한다★ — `2026-09` 같은 월 폴더는 트리의 `YYYY-MM/` 자리에
부합하면 "있는 것"이다. 달이 바뀔 때마다 트리를 고치지 않는다.

★반대 방향은 반증이 아니다★ — **여기 있는데 실제로 없는 건 정상이다.**
계기가 아직 안 생겨 안 만든 것이고, 그게 9장이 시킨 것이다. 빈 것을 미리 만들지 않는다.

> **이 문서가 구조의 정본이다** — 루트 CLAUDE.md 1장과 갈라지면 여기가 이긴다.
> 여기는 ★"무엇이 어디 있나"만★ 답한다. 왜 이렇게 나누는지(수명 3분류)는 1장,
> 무엇을 언제 만드는지(계기)는 0장, 이름을 어떻게 짓는지는 2장이 갖는다.

## 트리

```
docs/
  CLAUDE.md                ← 규칙 · docs 공통
  00_구조.md               ← 이 문서 · 상시
  01_기술스택.md           ← 상시 · 무엇으로 만드나
  02_만드는것.md           ← 상시 · 무엇을 · 왜 · ★무엇은 아닌가★
  03_결정대장.md           ← 상시 · 사용자가 정해야 할 것 (4장)
  04_…  05_…               ← 상시 · ☐ 계기가 생기면 그때 · ★뒤에 붙인다★ (2장)

  잠정/CLAUDE.md                          ← 규칙
  잠정/YYYY-MM-DD_제목.md                    계획 · ★월별로 안 가른다★
  진행중/CLAUDE.md                        ← 규칙
  진행중/YYYY-MM-DD_제목.md                  실행 · ★월별로 안 가른다★
  종결/CLAUDE.md                          ← 규칙
  종결/YYYY-MM/YYYY-MM-DD_제목.md            동결 · [종결]과 [폐기]가 같이 산다 ☐

  원본/CLAUDE.md                          ← 규칙
  원본/잠정/YYYY-MM/YYYY-MM-DD_제목.md       확정 시점 스냅샷      ☐
  원본/진행중/YYYY-MM/YYYY-MM-DD_제목.md     종결 시점 스냅샷      ☐

  회의록/YYYY-MM/YYYY-MM-DD_회의명.md        회의 정리본 · 읽는 곳  ☐
```

**☐ 는 "아직 없다"** — 첫 파일이 거기 갈 때 만든다. ★월 폴더를 미리 파두지 않는다★
(2026-09/ 를 8월에 만들면 그건 9월에 아무 일도 없었다는 거짓말을 한다).

**★번호에 빈 자리가 생겨도 메우지 않는다★** — `NN` 은 순서가 아니라 안정 ID다 (2장).
빈 번호는 무언가 빠졌다는 뜻이 아니라 **아무 뜻도 없다.** 새 문서는 뒤에 붙인다.

**각 CLAUDE.md 가 어느 장의 정본인지는 루트 CLAUDE.md 의 ★장 지도★가 갖는다** — 여기 안 적는다.

### 아직 없는 것 — 계기가 생기면 만든다

```
04_… 이후 상시 문서      "이건 끝나도 남는 지식"이 쌓였을 때 (0장 · 13장)
아키텍처 문서            ★스택이 정해진 뒤★ — 그전에 쓰면 상상도가 된다
NN_백로그.md             "고쳐야 하는데 지금은 아니다" 가 생겼을 때
점검 스크립트            눈으로 점검이 안 될 때 (11장)
아카이브/                물러날 파일(예: 더는 안 쓰는 상시 문서)이 ★실제로 처음 생겼을 때★ —
                         그때 규칙(어느 장이 정본인지)도 같이 정한다. 지금은 갈 파일이 없다
```

**왜 INDEX 를 따로 안 두나**: "전체 지도"가 두 파일로 갈리면 둘이 갈라진다 (8장).
읽는 순서는 구조의 한 측면이지 다른 문서가 아니다. **한 지도만 둔다** — 아래 `## 읽는 순서`.

## 읽는 순서

**번호는 ID이지 순서가 아니다** (2장). 처음 오는 사람이 읽을 순서는 ★여기가★ 갖는다.

```
1.  02_만드는것     무엇을 · 왜 · 무엇은 아닌가        ← ★여기부터★
2.  01_기술스택     무엇으로 만드나
3.  00_구조         (이 문서) 무엇이 어디 있나
4.  03_결정대장     지금 사용자 답을 기다리는 것
그다음  잠정/ 과 진행중/ 을 연다 — ★지금 무엇이 열려 있나★ (0장)
```

★이 순서가 번호와 다른 것은 정상이다.★ **번호를 이 순서에 맞추려고 옮기지 않는다** —
순서를 바꾸고 싶으면 ★이 절만 고친다★ (2장 · 그래서 이 절이 있다).

규칙 파일(`CLAUDE.md`)은 여기 안 넣는다 — 순서대로 읽는 게 아니라
**그 폴더를 만질 때 자동으로 딸려 온다** (0장).

## 폴더마다 문이 몇 개인가 — ★들어오는 문 하나, 나가는 문 하나★

```
폴더        들어오는 문                        나가는 문
─────────────────────────────────────────────────────────────────────────────
잠정/       "하기로 했다" 는 순간 (0장)        확정 → 진행중/ · 폐기 → 종결/    (5장)
진행중/     ★잠정/ 에서 온 것만★              종결·폐기 → 종결/YYYY-MM/        (6장)
종결/       진행중/ 에서 · 잠정 폐기에서       ★없다 — 여기서 끝난다★          (15장)
원본/       확정·종결 직전 복사 · 회의 원본    ★없다★                          (16장·7장)
회의록/     회의가 들어온 즉시                 ★없다★ — 내용만 다른 문서로 흐른다 (7장)
docs 루트   종결 이관(6장 ④) · 지식이 쌓였을 때(0장) · 회의 결정(7장)   ★없다★  (13장)
```

**나가는 문이 없는 곳은 무한히 쌓여도 된다** — ★왜인지는 9장 정본★.
그래서 전부 `YYYY-MM/` 으로 갈라 두고, `잠정/` `진행중/` 만 안 가른다 (2장).

**★사건 폴더는 들어오는 문이 하나라는 게 더 중요하다.★** `진행중/` 에 문서가 직접
태어나거나 `종결/` 에 뭔가 바로 꽂히면 계획이 없는 문서가 생기고, 그러면 "처음 생각과
어디가 달랐나"를 물을 대상이 사라진다 (14장).

★`docs 루트` 만 문이 여럿인 게 정상이다★ — 상시 문서는 사건이 아니라 **지식**이고,
지식은 사건이 끝날 때만 생기지 않는다. 여기서 하나로 조이면 회의에서 바로 정해진 것과
그냥 알게 된 것이 갈 곳을 잃는다. **대신 나가는 문이 없어서 총량이 관리된다** (13장).

## 한 사건은 파일이 몇 벌 되나

```
2026-08-12_ASOS수집.md 하나가 →  잠정/ → 진행중/ → 종결/2026-08/   ★이동★ (한 파일)
                          그리고 →  원본/잠정/2026-08/               ★복사★ (확정 시점)
                          그리고 →  원본/진행중/2026-08/             ★복사★ (종결 시점)
```

★세 곳에서 파일명이 같다★ — 그래서 이름 하나로 전부 찾힌다 (2장):

```
grep -r 2026-08-12_ASOS수집 docs/
```

월 폴더는 언제나 **파일명의 `YYYY-MM`**, 곧 잠정에서 태어난 달이다 (★2장 정본★).

★왜 두 번 복사하는지와 벌 수의 예외(폐기)는 16장이 정본★ — 여기는 위치만 적는다.
