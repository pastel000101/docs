## 2. 이름 규칙

```
상시   NN_영역_이름.md      ★날짜·버전을 넣지 않는다★
사건   YYYY-MM-DD_제목.md   ★잠정에서 태어난 날★ · 세 폴더를 지나도 안 바뀐다
```

**왜 상시에 날짜·버전을 안 넣나**: 계속 갱신되므로 이름이 거짓이 된다.
`v13_설계.md` 같은 이름은 곧 v6·v14 내용을 같이 담게 되고, **이름이 내용보다 좁아진다.**

**왜 사건 이름을 끝까지 고정하나**: 같은 파일이 `잠정/ → 진행중/ → 종결/` 로 옮겨 다니고
(0장), 그때마다 스냅샷이 `원본/` 에 쌓인다 (16장). 이름이 바뀌면 **한 사건의 네 벌이
서로 짝인지 알 수 없게 된다.** 이름 하나로 전부 찾을 수 있어야 한다:

```
grep -r 2026-08-12_ASOS수집   →  잠정 스냅샷 · 진행중 스냅샷 · 종결본 · 그걸 가리키는 링크
```

**진행 상태는 이름이 아니라 폴더가 갖는다.** `_계획` `_진행` 같은 접미사를 붙이면
폴더와 이름이 같은 것을 두 번 말하고, 옮길 때마다 둘이 갈라진다.

**`NN` 은 순서가 아니라 안정 ID다.** 읽는 순서는 INDEX 가 갖는다 (생기면).
번호가 곧 순서이면 03 과 04 사이에 새 문서가 필요할 때 번호를 밀어야 하고,
그건 이름 고정 위반이다. **양보할 쪽은 순서다.**
번호는 재사용하지 않는다 — 지운 자리는 비워둔다. **장 번호도 같다** (14·15·16 이 그래서 뒤에 붙었다).

### 날짜가 앞에 오고 ★계속 쌓이는 것★은 `YYYY-MM/` 으로 가른다

```
종결/YYYY-MM/        원본/잠정/YYYY-MM/     원본/진행중/YYYY-MM/
회의록/YYYY-MM/      원본/회의/YYYY-MM/
```

정기적으로 나는 것은 연 단위로 수십 개가 되고, flat 이면 폴더가 목록 구실을 못 한다.
**월 폴더는 언제나 파일명의 `YYYY-MM` 이다** — 옮긴 달이 아니다. 그래야 한 사건의
네 벌이 전부 같은 월 폴더에 놓여 짝 확인이 눈으로 된다 (15장).

반대로 `잠정/` `진행중/` 은 **안 가른다** — 열려 있는 것만 들어 있어 몇 건 안 되고,
가르면 **"몇 건이나 열려 있나"가 한눈에 안 보인다.**

**태어날 때 위치가 정해지는 것과 옮겨 다니는 것을 구별한다.**
회의록·원본은 생기는 순간 자기 월이 정해지고 다시 안 움직인다.
사건 문서만 옮겨 다니고, 그래서 **이동 절차에만 링크 확인이 붙는다** (5장 ④ · 6장 ⑥).

## 8. 정본과 사본 — 큰 문서를 나눌 때

파일이 커져 못 읽겠으면 **원래 파일은 그대로 두고 사본을 만든다.**

```
정본  원래 파일 그대로 (전체 검색·인용 기준)
사본  읽기용 — 나눠 담은 것
```

★이 장에서는 `정본` 으로만 부른다★ — `원본` 은 7·16장이 다른 뜻으로 쓴다 (원자료·스냅샷).

- 사본 머리말마다 **"정본은 X 다. 둘이 갈라지면 정본이 이긴다"**
- ★수정은 정본에만.★ 사본을 직접 고치면 두 벌이 조용히 갈라진다.
- 나누는 기준은 **정본이 이미 가진 구조**를 따른다 (날짜·장·안건) — 새로 만들지 않는다.
- **장 번호·항목 번호를 보존한다** — 다른 문서가 `N장 참조` 식으로 인용하게 된다.

## 9. 만들 기준과 지울 기준 — 둘이 한 쌍이다

### 새로 만드는 기준 — ★사건은 무조건 / 나머지는 안 만드는 게 기본★

```
사건 문서    하기로 했으면 ★무조건★ 잠정/ 에 하나 (0장의 문턱만 본다)
그밖에 전부  계기가 실제로 생겼을 때만
```

**이 둘을 섞지 않는다.** "안 만드는 게 기본"을 사건 문서에까지 적용하면
사건 문서는 한 번도 안 만들어진다 — 일을 시작하는 순간은 문서를 만들 마음이
가장 없는 순간이라, 억제 규칙이 거기 걸려 있으면 언제나 억제가 이긴다.
억제해야 하는 것은 **같은 사건을 여러 문서로 쪼개는 것**이지 사건 문서 자체가 아니다.

> **증상이 여럿인데 원인이 하나로 묶이면 → 그건 한 사건이다.** 문서도 하나다.
> 원인이 갈리면 그때 잠정 문서를 나눈다.

결정 항목도 같다 — **선택지가 표 한 줄이면 결정대장 · 근거를 펼쳐야 하면 사건 문서.**

INDEX·백로그·스크립트·항목 유형은 여전히 **미리 만들지 않는다**.
미리 만든 빈 것은 거짓말을 한다 — 사실은 "없다"가 아니라 "아직 쓸 일이 없었다"이다.

### 소멸 경로 — ★사건은 지워서가 아니라 옮겨서 빈다★

```
잠정/    확정되면 → 진행중/ 으로 이동 · 폐기되면 → [폐기] 달고 종결/ 로 (5장)
진행중/  종결되면 → 종결/YYYY-MM/ 으로 이동 (6장)
상시     틀린 줄은 지우고 맞는 내용으로 다시 쓴다 — ★"예전엔 X였다" 식 정정 흔적을 본문에 남기지 않는다★
결정①    '막히는 것'이 없어졌으면 지운다 (4장)
종결/    ★지우지 않는다★ — 그날의 실측이 여기 있다 (15장)
원본/    ★지우지 않는다★ — 원자료다 (16장)
```

**★잠정/ 과 진행중/ 은 지워서 비우는 폴더가 아니다.★** 지우면 계기와 계획이
같이 사라진다. **비우는 방법은 다음 칸으로 넘기는 것 하나뿐이고,
죽는 경우조차 [폐기] 를 달고 종결/ 로 간다.**

**왜 종결/ 과 원본/ 은 무한히 늘어도 되나**: 비용이 드는 성장은 **매번 읽는 곳**에서만
발생한다. 둘 다 `YYYY-MM/` 으로 갈려 있고 통째로 읽는 사람이 없으므로 아무리 늘어도
유지비가 0 이다. 반면 상시·①절·잠정·진행중은 매번 시야에 들어온다.
**소멸 경로는 거기에만 단다.**

**관리 비용의 근본 해법은 분류가 아니라 흐름이다.** 각 폴더에 나가는 문이 하나씩 있고,
그 문이 다음 폴더로 이어져 있으면 총량은 늘어도 **보이는 양은 안 는다.**

지운 기록은 버전 관리가 갖는다 (쓰게 되면). 문서에 개정 이력을 쌓지 않는다 —
`결정완료/` 와 같은 이유로 그것도 반드시 낡는 사본이다.

## 10. 한 이름이 두 뜻을 겸하지 않게

새 식별자(`Q1`·`D1`·`BR-x`)를 도입하기 전에 **기존 문서에 같은 토큰이 있는지 찾아본다.**
충돌하면 **나중에 만든 쪽**을 바꾼다 (종결·원자료 문서는 손대지 않는다).

**왜**: 한 토큰이 두 뜻을 겸하면 그걸 참조하는 모든 문장이 애매해지고,
나중에 분리하려면 두 뜻이 섞인 문장을 전부 다시 읽어야 한다.

★사건 제목도 식별자다★ — 같은 날 같은 제목이 두 개면 파일명이 겹치고,
그러면 스냅샷 네 벌이 서로를 덮어쓴다. 제목을 짓기 전에 `잠정/` `진행중/` 을 본다.

## 11. 점검 — 손으로 한다

**스크립트를 짜지 않는다.** 문서 스무 개까지는 눈으로 다 보이고,
없는 문제를 위해 짠 도구는 유지비만 남는다 — 정작 필요할 때쯤엔 규약이 달라져 있다.

문서를 크게 만졌을 때 아래를 훑는다:

```
흐름 — ★문서가 다음 칸으로 안 넘어가고 고여 있나★
  · 잠정/ 에 확정 조건이 이미 충족된 문서가 남아 있나 → 진행중/ 으로 갔어야 한다
  · 진행중/ 에 계획 항목이 전부 [x]/[~]/[-] 인 문서가 남아 있나 → 종결됐어야 한다
  · 진행중/ 문서의 `## 실행` 이 비어 있나 → 실행 중에 안 쌓고 있다 (14장)
  · 종결/ 문서와 원본/진행중/ 스냅샷이 짝이 맞나 (같은 YYYY-MM/ · 같은 파일명)
  · 진행중·종결 문서에 잠정 스냅샷이 있나 (원본/잠정/ 에 같은 이름)
  · 종결 후에 고쳐진 흔적이 있나 → 새 잠정으로 갔어야 한다 (15장)

구조 — 보면 바로 알 수 있는 것
  · ★폴더 위치와 머리말 상태 표기가 맞는가★ (갈라지면 폴더가 이긴다 — 1장)
  · 이름 규칙 (상시 NN_ · 사건 YYYY-MM-DD_) · NN 중복 · 같은 날 같은 제목
  · 사건 문서에 계기·하기로 한 것·확정 조건·종결 조건이 있는가 (3장)
  · 사본에 정본 표기가 있는가 (회의록이면 ★원본★ 표기)
  · `가정` 칸 ↔ 결정대장 ①절 행이 ★양방향으로★ 걸려 있는가
  · 회의록 ↔ 원본/회의 가 같은 YYYY-MM/파일명으로 짝이 맞는가
  · 회의록 머리말이 가리키는 곳(①-N · 사건 문서)이 실재하는가

의미 — 읽어야 알 수 있는 것
  · 장 번호 인용이 여전히 유효한가
  · 낡은 사실(옛 파일명·옛 날짜)이 남았는가
  · 같은 항목의 상세가 두 곳에 있는가
```

**아래 넷은 지적 대상이 아니다** — 낡은 게 아니라 일부러 그런 것이다:

```
· "옛 이름 → 새 이름" 대조표
· "「X」는 틀렸다" 형태의 정정문
· 원자료(원본·회의록·아카이브) 안의 옛 표기 — 당시 사실이라 고치면 안 된다
· ★원본/ 스냅샷 안의 깨진 링크★ — 그때는 거기 있었다는 정보다 (16장)
```

**언젠가 스크립트를 짠다면** '흐름'과 '구조' 항목만 넣는다 — 둘 다 파일 위치와
머리말 문자열만 보면 판정된다. '의미' 쪽은 정규식으로는 오탐이 구조적으로 나고,
**오탐투성이 검사기는 없느니만 못하다** — 무시하는 습관이 들면 진짜 지적도 놓친다.
죽는 건 그 항목이 아니라 검사 전체의 신뢰다.

## 13. 상시 문서 머리말 — 두 줄

```
최종 확인: YYYY-MM-DD
반증 조건: 무엇을 보면 이 문서가 틀렸다고 알 수 있나 (파일·명령·수치)
           실행 가능한 게 없으면 → ★`없음 — 이 문서는 합의다`★
재론 조건: 반증 조건이 '없음'일 때만 쓴다. 누가 무엇을 문제 삼으면 다시 여나
```

**설정·구조 문서는 명령으로 쓸 수 있지만 원칙·합의 문서는 못 쓴다.** 억지로 채우면
"훑어보라" 수준의 문장이 들어가고, 그건 아래에서 실행 불가능하다고 한 바로 그 형태다.
`없음` 을 정식 값으로 두면 **빈칸(빠뜨림)과 없음(판단)이 구분되어** 11장 점검이 성립한다.

`없음` 이 도피처가 되지 않게 **재론 조건이 대신 들어간다.**

**왜**: 사건에는 종결 조건이, 결정에는 대장이 있는데 상시에는 아무 트리거도 없다.
그런데 상시는 CLAUDE.md 가 가리키는 대상이다 — **가장 신뢰받는 문서가 가장 검증이 안 된다.**
"낡았는지 훑어보라"는 지시는 실행 불가능하고,
"이 명령의 출력과 다르면 낡은 것"은 실행 가능하다.

**상시 문서는 파이프라인을 타지 않는다.** 잠정에서 태어나지 않고, 종결되지도 않는다 —
사건이 종결될 때 그 지식이 **이관되어 오는 곳**이다 (6장 ③).
