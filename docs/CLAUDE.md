## 2. 이름 규칙

```
상시   NN_영역_이름.md      ★날짜·버전을 넣지 않는다★ — 갱신되는 문서는 이름이 거짓이 된다
사건   YYYY-MM-DD_제목.md   ★잠정에서 태어난 날★ · 세 폴더를 지나도 안 바뀐다
```

★사건 이름이 고정이라 이름 하나로 한 사건의 ★있는 벌 전부★가 찾힌다★ (완주면 대개
세 벌 · 벌 수 예외는 16장 · 04_규약근거.md 2장):
`grep -r 2026-08-12_ASOS수집` → 잠정 스냅샷 · 진행중 스냅샷 · 종결본 + 그걸 가리키는 링크들.

**진행 상태는 이름이 아니라 폴더가 갖는다** — `_계획` `_진행` 접미사 금지. 같은 것을
두 번 말하면 옮길 때마다 둘이 갈라진다.

**`NN` 은 순서가 아니라 안정 ID다.** 읽는 순서는 `00_구조.md` 의 `## 읽는 순서` 가 갖는다 —
앞에 오게 하고 싶으면 번호가 아니라 그 절을 고친다. **번호는 재사용하지 않는다** —
지운 자리는 비워두고 새 문서는 ★뒤에 붙인다★. **장 번호도 같다.** 옛 번호를 인용한
문장이 조용히 다른 뜻이 되기 때문이다 (04_규약근거.md 2장).

★번호 재배치는 2026-08-12 에 한 번 했고 다시는 없다★ — 그 이전의 "01" 인용은
결정대장을 가리킨다 (대조표: 04_규약근거.md 2장).

### 날짜가 앞에 오고 ★계속 쌓이는 것★은 `YYYY-MM/` 으로 가른다

```
종결/YYYY-MM/   원본/잠정/YYYY-MM/   원본/진행중/YYYY-MM/   회의록/YYYY-MM/   원본/회의/YYYY-MM/
```

**월 폴더는 언제나 파일명의 `YYYY-MM` 이다** — 옮긴 달이 아니다 (한 사건의 벌들이
같은 월 폴더에 놓여 짝 확인이 눈으로 된다 · 04_규약근거.md 2장).
`잠정/` `진행중/` 은 ★안 가른다★ — "몇 건이 열려 있나"가 한눈에 보여야 한다.
회의록·원본은 생기는 순간 자기 월이 정해져 다시 안 움직인다 — 사건 문서만 옮겨
다니고, 그래서 이동 절차에만 링크 확인이 붙는다 (5장 ④ · 6장 ⑥).

## 8. 정본과 사본 — 큰 문서를 나눌 때

파일이 커져 못 읽겠으면 **원래 파일은 그대로 두고 사본을 만든다.**
★이 장에서는 `정본` 으로만 부른다★ — `원본` 은 7·16장이 다른 뜻으로 쓴다.

- 사본 머리말마다 **"정본은 X 다. 둘이 갈라지면 정본이 이긴다"**
- ★수정은 정본에만.★ 사본을 직접 고치면 두 벌이 조용히 갈라진다.
- 나누는 기준은 **정본이 이미 가진 구조**(날짜·장·안건) — 새로 만들지 않는다.
- **장 번호·항목 번호를 보존한다** — 다른 문서가 `N장 참조` 식으로 인용한다.

### ★결론은 반복해도 되고, 근거는 한 곳에만★ — 규칙 파일끼리도 같다

```
반복해도 된다  한 줄 결론 — 짧아서 갈라져도 눈에 띈다
★한 곳만★     여러 줄 근거 문단 — 나머지 자리에는 ★"04_규약근거.md N장"★ 만 적는다
```

실제로 갈라진 것은 전부 근거 쪽이었다 (사례: 04_규약근거.md 8장). 근거를 옮기고
싶어지면 그건 정본이 틀렸다는 신호다 — 사본 자리에 덧붙이지 말고 정본을 고친다.
두 곳을 다 고쳐야 할 것 같으면 **정본이 어디인지부터 정한다** (10장).

## 9. 만들 기준과 지울 기준 — 둘이 한 쌍이다

```
사건 문서    ★지금★ 하기로 했으면 무조건 잠정/ 에 하나 (0장의 문턱만 본다 ·
             유예된 합의는 백로그)
그밖에 전부  계기가 실제로 생겼을 때만
```

억제해야 하는 것은 사건 문서 자체가 아니라 **같은 사건을 여러 문서로 쪼개는 것**이다:

> **증상이 여럿인데 원인이 하나로 묶이면 → 한 사건 · 문서도 하나.** 원인이 갈리면 그때 나눈다.

결정 항목도 같다 — **선택지가 표 한 줄이면 결정대장 · 근거를 펼쳐야 하면 사건 문서.**
백로그·스크립트·항목 유형·월 폴더는 미리 만들지 않는다 (0장). ★빈 것과 규격을
구별한다★ — 규격이 곧 내용인 문서(`01_기술스택`)는 껍데기가 아니다 (04_규약근거.md 9장).

### 소멸 경로 — ★사건은 지워서가 아니라 옮겨서 빈다★

```
잠정/    착수 → 진행중/ 이동 · 폐기 → [폐기] 달고 종결/ 로 ★스냅샷 없이★ (5장)
진행중/  종결·폐기 → 종결/YYYY-MM/ (6장 · 접어도 같은 문으로 나간다)
상시     틀린 줄은 지우고 다시 쓴다 — ★"예전엔 X였다" 식 정정 흔적을 본문에 안 남긴다★
결정①    '막히는 것'이 없어졌으면 지운다 (4장)
백로그   활성화되면 새 잠정이 내용을 ★이어받은 것을 확인한 뒤★ 항목을 지운다 (7장)
         마지막 항목이 빠져 비면 문서째 지운다 — 다시 만들 땐 ★새 NN★ (2장 · 재사용 금지)
근거     지정 규칙 파일 어느 것도 그 장을 참조하지 않고 대조표(HC)도 아니면 그
         ★장★을 지운다 — 판정 단위는 장이다 (04_규약근거.md 18장)
종결/ 원본/  ★지우지 않는다★ — 그날의 실측·원자료다 (15·16장)
```

★잠정/·진행중/ 은 지워서 비우는 폴더가 아니다★ — 비우는 방법은 다음 칸으로 넘기는 것
하나뿐이고, 죽는 경우조차 [폐기]를 달고 종결/로 간다. 종결/원본이 무한히 늘어도 되는
이유는 04_규약근거.md 9장 — 비용이 드는 성장은 매번 읽는 곳에서만 발생한다.
지운 기록은 git 이 갖는다 — **문서에 개정 이력을 쌓지 않는다.**

## 10. 한 이름이 두 뜻을 겸하지 않게

새 식별자(`Q1`·`D1`·`BR-x`)를 도입하기 전에 **기존 문서에서 같은 토큰을 찾아본다.**
충돌하면 ★나중에 만든 쪽★을 바꾼다 (종결·원자료 문서는 손대지 않는다) — 한 토큰이
두 뜻을 겸하면 참조하는 모든 문장이 애매해진다 (04_규약근거.md 10장).
★사건 제목도 식별자다★ — 제목을 짓기 전에 `잠정/` `진행중/` 을 본다
(같은 날 같은 제목이면 그 사건의 벌들이 서로를 덮어쓴다).
