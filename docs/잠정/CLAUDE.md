# 잠정/ — 계획. 사건이 태어나는 곳 · 3 · 5장 정본

> **하기로 했으면 무조건 여기부터다.** 예외 없다 (0장의 문턱만 본다).
> ★이 파일은 잠정 문서를 ★열기 전에★ 읽는다 — 쓰기 시작하면 규격이 이미 늦는다 (0장).
> 이 폴더가 비어 있다는 건 "지금 계획 단계인 일이 없다"는 뜻이지, 정상 상태라는 뜻이 아니다.
> 장문 근거·반례는 04_규약근거.md 3장·5장 — 판정이 애매할 때만 그 장을 연다.
> 최종 확인: 2026-08-17
> 반증 조건: 없음 — 규칙은 합의다 (13장)
> 재론 조건: ★여섯 칸 중 못 채우는 칸이 나왔을 때★ · 확정 조건에 뭘 적을지 모르겠을 때 ·
>            계기로 쓸 사람의 말이 없을 때

## 3. 사건 문서는 ★잠정에서★ 태어난다 — 머리말 여섯 칸

파일명은 `YYYY-MM-DD_제목.md` — 날짜는 태어난 날이고 끝까지 안 바뀐다 (2장).
제목을 짓기 전에 잠정/·진행중/ 에 ★같은 날 같은 제목★이 없나 본다 (10장 —
겹치면 스냅샷 세 벌이 서로를 덮어쓴다).

```
계기:         왜 하기로 했나 — ★사용자 말 원문 그대로★ (요약 금지)
하기로 한 것: 항목 목록 — ★진행중에서 이걸 하나씩 처리한다★
확정 조건:    무엇이 있어야 진행중으로 넘기나 (아래 5장)
종결 조건:    누가 무엇을 보면 닫나 — 가능하면 숫자로
가정:         결정이 안 난 채 깔고 가는 것 + ★뒤집힘 비용★ (없으면 `없음`)
상시로 갈 것: (빈 칸으로 시작 — 진행중에서 한 줄씩 쌓는다 · 14장)
```

**여섯 칸은 ★전부 필수★다.** 빈 칸(빠뜨림)과 `없음`(판단)은 다르다 (13장).
조건부로 나중에 붙는 것: `## 실행` 절(확정 대기 중 진행분 · 아래 5장) ·
`앞 사이클:`(재작업 · 15장) · 상태 표기 `[종결]`/`[폐기]`(닫을 때 · 6장 ③).

### `계기` — 원문을 고치지 않는다 · 해석은 인용 밖에

- ★요약하면 값이 사라진다★ — 원문 한 문장이 결론 전체를 지탱한다 (04_규약근거.md 3장).
- 계기는 ★그 문서를 열게 만든 그 말 하나★다 — 대개 한두 줄. 배경 자료·남이 써준
  권고문은 계기가 아니라 `하기로 한 것` 의 근거다. ★사람의 말만 계기가 된다★ (7장).
  판별: "이 말이 없었어도 이 문서를 열었을까?" — 열었다면 계기가 아니다.
- 한 인용이 두 사건의 계기로 동시에 쓰이면 둘 다 틀렸다.
- 대화 로그는 자동 저장된다 (`~/.claude/projects/<프로젝트>/*.jsonl`) —
  손으로 다시 쓰지 않는다. 필요한 건 ★결정의 계기★뿐이다.

지시가 나눠서 올 때 — `계기` 는 태어날 때 한 번 적고 끝이다:

```
잠정을 열게 만든 첫 지시   → `계기` 칸. ★이후로 안 고친다★
그 뒤에 온 지시            → 진행중 문서의 `## 계획 밖` 에 ★원문으로★ (14장)
아직 잠정에 있을 때 왔다   → `하기로 한 것` 에 항목 추가 · 계기는 그대로 둔다
```

이어붙이면 "처음"과 "변경"이 한 덩어리가 되어 둘 다 안 보인다 (04_규약근거.md 3장).

### ★비밀은 원문에서 뺀다★ — 유일한 예외

인증키·비밀번호·개인정보는 ★그 부분만★ 대괄호로 치환한다:
`> 일반 인증키 〔키 원문 — 여기 옮기지 않는다〕`
요약이 아니다 — 무엇이 있었는지는 남기고 값만 뺀다. ★빈 자리로 두지 않는다.★
원본/에 박히면 지울 길이 없다 (04_규약근거.md 3장).
★이미 새어나간 것은 결정대장에 올려 재발급을 묻는다★ (4장).

### `하기로 한 것` — ★체크 가능한 항목으로 쪼갠다★

한 문단으로 쓰면 "다 했나"를 판정할 수 없다. **모르는 것도 항목으로 적는다** —
"쿼터가 얼마인지 모른다"가 아니라 **"쿼터 한도를 실측한다"** 다. 계획은 아는 것의
목록이 아니라 ★할 일의 목록★이다. 이게 있어야 진행중이 쌓을 대상을 갖는다 —
없으면 회고가 된다 (04_규약근거.md 3장).

### `종결 조건` — 누가 무엇을 보면 닫나

★관찰자가 지금 실재해야 한다★ — 아직 안 정해진 역할("팀"·"담당자"·"라벨러 2명")을
적으면 없는 사람을 기다리는 문서가 되고, 조건이 있어 보여 점검에도 안 걸린다
(04_규약근거.md 3장). 그 역할이 결정 대기 중이면 그 결정을 ★확정 조건으로 올린다★ —
종결 조건에 숨기지 않는다.

### `가정` 과 ★뒤집힘 비용★

```
가정:        어느 결정이 안 나서 뭘 깔고 가나 — ★결정대장 ①-N 링크★
뒤집힘 비용: 결정이 반대로 나면 무엇을 되돌려야 하나 — 파일·작업량으로
```

`막히는 것`(4장) = 결정을 앞당길 이유 · `뒤집힘 비용` = 미룰 수 없는 이유 — 둘이 짝이다.
★양방향 링크★: 결정대장 ①-N 행 ↔ 이 문서 `가정` 칸 · ★파일명만 · 폴더 안 적는다★ (4장).
역링크가 없으면 가정이 조용히 살아남아 결정을 이긴다 (04_규약근거.md 3장).

## 5. 확정 — 잠정에서 진행중으로

```
사용자 확정이 필요하다   → ★결정대장 ①-N 링크★ · 그 답이 확정 조건이다
내가 재면 풀린다        → 무엇을 재면 되나 · ★재고 나서 스스로 확정한다★
확정할 게 없다          → `없음 — 계획 그대로 간다` ★이게 가장 흔하다★
```

★잠정은 승인 절차가 아니다★ — 사용자를 기다리는 건 ①절이 확정 조건일 때뿐이다
(04_규약근거.md 5장).

`가정` 에 뒤집힘 비용을 적었으면 ★시제로★ 판별한다 (04_규약근거.md 5장):

```
뒤집힘 비용이 ★이미 만든 것을 고쳐야 한다★ 급이다  → 그 결정을 확정 조건으로 올린다 (①-N)
"반대로 나면 무엇을 ★버리게★ 되나" 에 답이 있다   → 올린다 — 대규모 수정도 이쪽이다
★종결 조건의 관찰자★가 그 결정에 걸려 있다        → 올린다 (3장)
"무엇을 ★더 하게★ 되나" ★뿐★이다                 → `없음` 으로 간다
```

지금 막힌다(답 없이 다음 단계 불가)면 확정 조건이 아니라 ★바로 묻는다★ (4·17장).

★확정을 기다리는 동안에도 막히지 않는 부분은 진행한다★ — 결과는 `## 실행` 절을 열어
거기 적는다 (14장과 같은 절이다). 진행중으로 옮기는 것만 확정 뒤다. 스냅샷은 실행분도
포함해 그 시점 그대로 뜬다 (04_규약근거.md 5장).

### 확정되면 — ★순서가 중요하다★

```
① 확정 조건 칸을 결과로 바꾼다 (확정일 · 무엇으로 확정됐나 한 줄)
② ★원본/잠정/YYYY-MM/ 에 이 시점 그대로 복사★ (16장)
③ 그다음 파일을 진행중/ 으로 ★이동★ (이름 안 바꾼다)
④ ★경로가 박힌 링크만★ 고친다 (회의록 머리말 등 · 결정대장 `사건` 칸은 파일명뿐이라 무관)
```

★②를 건너뛰면 계획이 실행에 덮인다 — 스냅샷을 먼저 뜨고 옮긴다★ (04_규약근거.md 5장).

### 확정 안 되고 죽는 길

```
계기가 사라졌다        → 머리말을 [폐기]로 (폐기일 · 왜 죽었나 한 줄)
                        ★스냅샷 없이★ 바로 종결/YYYY-MM/ 으로
계획이 통째로 틀렸다   → 위와 같이 [폐기] + 새 잠정 문서를 연다 (15장과 같은 모양)
```

스냅샷이 없는 이유는 "실행이 없어서"가 아니라 ★뒤에 다시 쓰는 단계가 없어서★다
(04_규약근거.md 5장). 결과 없음도 결과다 — 폐기 문서가 없으면 반년 뒤 같은 것을
다시 계획한다. ★잠정 문서를 그냥 지우지 않는다★ — 지우면 계기까지 같이 사라진다.
